## Ход работы

### 1. Данные и разбиение

Каждая строка файла — фрагмент диалога с форума:

| Колонка | Содержимое |
|---|---|
| `Reply 1 original` | исходная реплика, на которую отвечают (контекст) |
| `Reply 2 original` | ответ на неё — оригинальный текст с оскорблением |
| `Identifiers` | ключевые слова, по которым строка попала в датасет |
| `target_group` | группа, на которую направлена агрессия |
| `Reply 2 original dialogue 1/2` | короткие вежливые реплики-ответы на `Reply 1` — судя по стилю, сгенерированные нетоксичные альтернативы; с оригиналом не пересекаются |

Целевой текст — `Reply 2 original`: единственный «живой» текст, к которому относится разметка. Ключевое слово из `Identifiers` встречается в нём в ~77% строк, а в `Reply 1` — лишь в ~9%. Класс для стратификации — `target_group`.

**Метки шумные.** Класс выведен из ключевых слов, а не размечен по смыслу: из 537 наборов `Identifiers` 94.8% однозначно задают класс. «Блядь», «сука» → `women`, хотя часто это просто междометия без агрессии к женщинам; «пидор», «хуесос» встречаются сразу в `lgbt`, `man` и `other`. Здесь класс нужен только для стратификации, так что на результаты это не влияет, но в задаче классификации такой шум ограничивал бы достижимое качество.

Две проблемы, найденные до разбиения:
- в разметке 25 строк с классом `migrant` при основном `migrants` — слил;
- 3112 полных дубликатов текста (один ответ встречается в нескольких диалогах). Удалил **до** сплита: иначе одинаковые тексты окажутся и в Train, и в Test, и перплексия языковой модели будет нечестно занижена.
- дубли — это 2115 разных текстов, повторённых до 13 раз (видимо, один `Reply 2` записан в нескольких строках с разными `dialogue 1/2`). У 1328 из них копии размечены **разными** классами — ещё одно подтверждение шумности меток. `drop_duplicates` оставляет метку первой копии; для стратификации этого достаточно.

После дедупликации 7270 документов → Train 5816 / Test 1454, стратификация выдержана с точностью до 0.1% по каждому классу.

### 2. Структура Train

| | слов | символов |
|---|---|---|
| среднее | 28.1 | 171.2 |
| медиана | 23 | 137 |
| максимум | 94 | 517 |

Распределение длин скошено вправо (типично для коротких форумных реплик): пик на 8–15 словах и длинный хвост. Стоп-слова NLTK составляют 37% всех токенов; топ — «и», «не», «в», «на», «ты», «что». Заметно высокая позиция «ты» и «тебя» — это прямые обращения, характерные именно для оскорблений.

Готовый список NLTK проверен на Train, и у него нашлись пробелы: нет «это» (1598 употреблений) и «тебе» (486), хотя «тебя» есть; при этом внутри лежат смысловые «хорошо», «лучше», «конечно», «два», «три». Для hate speech часть стоп-слов важна — обращения на «ты/вы» и отрицания «не/нет/ни». Поэтому собран доменный список: NLTK + «это», минус обращения и отрицания — 144 слова, покрывает 33.3% токенов вместо 37.4%.

Стоп-слова в этой работе только анализируются и **нигде не удаляются**: N-граммная модель моделирует порядок всех слов, и без служебных слов пострадали бы и грамматика, и смысл («ты не прав» → «прав»). Доменный список пригодится для классификации по мешку слов / TF-IDF.

### 3. Шум

Проверял 20 регулярных выражений на Train, для каждого — число документов и примеры совпадений.

| тип шума | доля документов | решение |
|---|---|---|
| числа («911», «8-й», «2ch», «250к») | 19.3% | → `[NUM]` |
| КАПС (слово из 3+ заглавных) | 13.0% | только анализ, регистр приводится к нижнему |
| неразрывные / двойные пробелы | 3.9% / 2.0% | → обычный пробел |
| латиница (ники, «webm», «jpg», игровые термины) | 3.6% | → `[LAT]` |
| растянутые буквы («ииииии», «сукааа») | 3.5% | 3+ подряд → 1 буква |
| многоточия | 3.0% | удаляются вместе с пунктуацией |
| эмоциональная пунктуация («!!!», «?!») | 2.3% | → `[EMPH]` |
| скобочные смайлы («)))», «((») | 1.8% | → `[SMILE]` / `[SAD]` |
| смешение алфавитов в слове («Укрaбина», «всë») | 0.9% | латинские двойники → кириллица |
| символ `@` как разделитель @-паст | 0.4% | → пробел |
| «эхо» `(((слово)))`, эмодзи, #хэштеги, e-mail | <0.1% | → `[ECHO] слово`, `[EMOJI]`, `[TAG]`, `[EMAIL]` |
| типографика («», —, …, ♣) | 46 уникальных символов | удаляется |
| **URL, HTML-теги, HTML-сущности, @ники, переводы строк** | **0** | правила есть, но не срабатывают |

Отсутствие URL и HTML **доказано** нулём совпадений регулярок — авторы датасета вырезали их при сборе. Отдельно проверил все символы вне «нормального» алфавита (кириллица, латиница, цифры, базовая пунктуация): их всего 46 уникальных / 777 вхождений, ничего неожиданного (слэши, проценты, кавычки-ёлочки, тире).

Находки, специфичные для домена:
- **`@` — не упоминания.** На 2ch `@` разделяет пункты «@-пасты»: `ПЫТАЕШЬСЯ ШУТИТЬ@ВЫГЛЯДИШЬ КАК КЛОУН@…`. Первая версия конвейера заменяла `@\w+` на `[USER]` и съедала русские слова («@НЕ», «@ПЫТАЕШЬСЯ»). Настоящих ников вплотную к `@` нет (два ника с пробелом после `@`, латиницей — уходят в `[LAT]`), есть один e-mail.
- **Маскировка латиницей.** Часть русских слов записана с латинскими двойниками букв («Укрaбина», «прoлaпсошизикe», «CЫН», «всë») — обход фильтров модерации. Без исправления токенизатор разрезал бы такие слова на куски.
- **Эмоциональные сигналы.** «!!!», «?!», «)))» для человека — явные маркеры агрессии и издёвки («тупой хохол)))»), а `(((слово)))` — известный антисемитский маркер «эхо». Они сохраняются спец-токенами, а не удаляются.
- **КАПС** (крик) встречается в 13% документов, но в токены не превращается: регистр приводится к нижнему, чтобы «БЛЯДЬ» и «блядь» были одним словом, а метка перед каждым словом капсом раздула бы текст. Это признак для будущей классификации, а не для языковой модели.

### 4. Конвейер очистки

19 правил на `re`, каждое отвечает за один тип шума, порядок фиксирован (e-mail раньше `@`; «эхо» раньше смайлов; числа и латинские двойники раньше латиницы, чтобы «2ch» и «Укрaбина» не распались). В ноутбуке есть пошаговая трассировка правил на примере.

Ключевые решения:
- **Leet перед числами:** отдельные цифры внутри русского слова (`0→о`, `1→и`, `3→з`, `4→ч`, `6→б`, `7→т`, `8→в`) заменяются на буквы, если слово начинается и заканчивается русской буквой и содержит минимум 4 русские буквы: `стукач0к → стукачок`. Числовые записи `5ооо рублей → [NUM] рублей` сохраняют прежнюю обработку. Это ограниченная эвристика; латинские ники, крайние цифры и группы цифр не декодируются.
- **Эмоциональные сигналы — токенами**: «!!», «?!» → `[EMPH]`, «)))» → `[SMILE]`, «((» → `[SAD]`, `(((слово)))` → `[ECHO] слово`. Одиночные «!» и «?», многоточия удаляются вместе с остальной пунктуацией: это обычная интонация, а не усиление.
- **`@` → пробел** (разделитель паст), латинские двойники внутри русских слов → кириллица.
- **Спец-токены вместо удаления** для чисел, латиницы, ссылок, ников, e-mail, эмодзи. Для языковой модели важно, что «после “купил за” идёт число», а не какое именно; удаление сломало бы контекст, а сохранение — размазало бы вероятность по тысячам уникальных чисел.
- **Схлопывание, а не удаление** растянутых букв: «лоооох» → «лох». В русском нет слов с тремя одинаковыми буквами подряд, так что правило «3+ → 1» безопасно, а «нн», «сс» не трогает.
- **ё → е**: в форумном тексте «ещё»/«еще» пишут вперемешку, это раздувало бы словарь и портило бы поиск опечаток.
- Нижний регистр применяется **до** правил: латиница и ё ищутся в нижнем регистре, а спец-токены вставляются в верхнем и потому не попадают под последующие правила.
- Пунктуация удаляется **последней** — только когда все содержательные классы уже обработаны. Токенизатор извлекает спец-токены и кириллические слова (включая дефисные: «кто-то»).
- В конце каждый документ оборачивается в `<s> … </s>`.

Примеры:
- `@vasya ну ты и лоооох, GG WP, 2ch рулит, купил за 250к #позор` → `<s> [USER] ну ты и лох [LAT] [LAT] [NUM] рулит купил за [NUM] [TAG] </s>`
- `ПЫТАЕШЬСЯ ШУТИТЬ@ВЫГЛЯДИШЬ КАК КЛОУН))) а Укрaбина всë?! пиши на anon@yandex.ru` → `<s> пытаешься шутить выглядишь как клоун [SMILE] а украбина все [EMPH] пиши на [EMAIL] </s>`

В Train после очистки: `[NUM]` 1811, `[LAT]` 622, `[EMPH]` 169, `[SMILE]` 107, `[EMOJI]` 21, `[SAD]` 13, `[ECHO]` 5, `[TAG]` 5, `[EMAIL]` 1.

После добавления leet-обработки ноутбук выполнен заново. Актуальные метрики и примеры находятся в выводах `notebook.ipynb`; остальные численные сравнения и примеры ниже в README описывают исходный запуск и могут немного отличаться.

### 5. Стемминг vs лемматизация

| | уникальных токенов | сокращение |
|---|---|---|
| без нормализации | 37 470 | — |
| стемминг (Snowball) | 21 571 | −42.4% |
| лемматизация (pymorphy3) | 22 666 | −39.5% |
| гибрид (лемма для словарных слов, стем для остальных) | 21 860 | −41.7% |

Ключевое наблюдение — разбить словарь на слова, известные pymorphy3, и неизвестные ему:

| слова | уникальных | стемминг | лемматизация |
|---|---|---|---|
| словарные | 27 103 | −49.4% | −49.5% |
| вне словаря (мат, сленг, искажения) | 10 366 (27.7% словаря, 10.8% употреблений) | −19.5% | −12.9% |

**Выводы.**
- **На словарных словах методы сжимают словарь одинаково**, но лемматизация качественнее. Стеммер склеивает разные слова: 2383 стема объединяют больше одной леммы, например стем «он» ← «он/она/они/оный». И наоборот, разносит формы одного слова: 1384 леммы дают больше одного стема («быть» → «буд/будет/был/быт…», «идти» → «ид/идет/шел/шла»). Лемматизатор знает супплетивные формы, стеммер — нет.
- **Вся разница в размере словаря — из слов вне словаря OpenCorpora.** Здесь стемминг последовательнее: «долбоеб/долбоебы/долбоеба/долбоебом» → один стем «долбоеб», а pymorphy3 угадывает разные и часто несуществующие леммы: «долбоести», «долбоебова», «руснить» (для «русня»), «хуесоса». Лемматизатор меньше сжал мат не потому, что бережнее с ним обращается, а потому, что **разбросал его формы** по мусорным леммам. (Не всегда: на «уебок/уебки/уебан» оба метода одинаково дробят.)
- Для hate speech это критично: ключевые для задачи слова — оскорбления и сленг, то есть ровно та часть словаря, где лемматизация слабее всего. Часть «жадных» склеек стеммера в ноутбуке (стем «еб» ← «еба», «ебася», «ебучаять»…) тоже объясняется кривыми леммами-догадками pymorphy3, а не только ошибками стеммера.
- **Вывод для домена:** лучший вариант — **гибрид** (лемма для словарных слов, стем для остальных): точность на нормальной лексике + последовательность на мате. Если выбирать один метод — для этого корпуса предпочтительнее **стемминг**: его склейки на нормальных словах менее вредны, чем разброс форм ключевых оскорблений у лемматизатора.
- Для языковой модели нормализация **не применялась**: модель должна генерировать согласованные словоформы, а не леммы или стемы.

### 6. Левенштейн и опечатки

**Реализация.** Алгоритм Вагнера–Фишера с двумя строками вместо полной матрицы: для ячейки $D[i][j]$ нужны только $D[i-1][j-1]$, $D[i-1][j]$, $D[i][j-1]$. Более короткая строка ставится «по горизонтали», так что память $O(\min(|a|,|b|))$. Проверено на известных значениях (`kitten/sitting` = 3, `привет/превед` = 2 и т.д.).

**Поиск пар.** Словарь Train (слова длиной ≥4) — 36 283 слова, наивный перебор пар — 650 млн вызовов, для чистого Python это часы. Использовал **индекс удалений** (идея SymSpell): для каждого слова генерируются все строки с ≤2 удалёнными символами; два слова с расстоянием ≤2 обязательно делят хотя бы один такой вариант. Индекс даёт 556 тыс. кандидатов вместо 650 млн, каждый **проверяется точным** `levenshtein`. Всё вместе — 3 секунды; найдено 239 163 пары (24 401 с расстоянием 1).

**Классификация.** Не всякая близкая пара — опечатка, поэтому пары разделены с помощью морфологии:

| класс | критерий | пар | примеры из топ-10 |
|---|---|---|---|
| формы одного слова | оба в словаре, одна лемма | 24 735 | тебе/тебя, сука/суки, было/быть |
| опечатка / искажение | одно слово в словаре, другое нет и редкое | 60 277 | тебя/тибя, просто/прото, только/толко, если/есле, тебя/утебя |
| разные слова («ложные друзья») | оба в словаре, разные леммы | 137 924 | меня/тебя, потом/потому, себя/тебя |
| оба вне словаря | сленг и его искажения | 16 227 | не ранжируются |

Топ-10 опечаток ранжирован по частоте *правильного* слова (чем частотнее слово, тем вероятнее, что редкий сосед — его искажение). Классификация эвристическая: «утебя» — слипшиеся слова, а не опечатка в строгом смысле; «еслиб» — разговорное слитное написание. Но все десять — реальные ошибки набора, и их нашёл наш алгоритм.

### 7–8. Языковая модель, сглаживание, перплексия

**Словарь.** Явный: токены Train с частотой ≥2 плюс `<s>`, `</s>`, `[UNK]` — 11 502 токена из 37 480 уникальных. Слова с частотой 1 заменяются на `[UNK]` **уже в Train**, иначе модель никогда не увидит `[UNK]` при обучении и не сможет оценить его вероятность на Test. Доля `[UNK]`: 14.9% в Train, 20.9% в Test — много, но это ожидаемо для форумного домена с огромным количеством одноразовых искажений.

**Модель** `NGramLM` хранит счётчики m-грамм и контекстов для всех m ≤ n и считает $P(w\mid h)$ в трёх режимах: MLE, add-k (Лаплас при k=1), линейная интерполяция Елинека–Мерсера. Проверено, что во всех режимах $\sum_w P(w\mid h) = 1$.

**Перплексия** через log-likelihood: $PP = \exp(-\frac{1}{N}\sum \log P(w_i\mid h_i))$. Произведение 42 тысяч вероятностей порядка $10^{-3}$ обнулилось бы в float; сумма логарифмов — нет.

**Подбор k и λ** — на dev-выборке (10% Train), причём словарь для подбора строится только по оставшимся 90%, ровно как словарь для Test строится по Train. Иначе часть слов dev была бы «в словаре», но с нулевой частотой, и интерполяция давала бы ∞ (первая версия наступила на эти грабли).

**Результаты на Test** (42 704 предсказанных токена):

| n | метод | PP (test) | нулевых событий |
|---|---|---|---|
| 2 | MLE, без сглаживания | **∞** | 13 726 (32.1%) |
| 2 | Лаплас, k=1 | 1469.4 | 0 |
| 2 | add-k, k=0.01 | 529.0 | 0 |
| 2 | интерполяция, λ=(0.4, 0.6) | **243.0** | 0 |
| 3 | MLE, без сглаживания | **∞** | 29 336 (68.7%) |
| 3 | Лаплас, k=1 | 5605.7 | 0 |
| 3 | add-k, k=0.005 | 2447.2 | 0 |
| 3 | интерполяция, λ=(0.1, 0.3, 0.6) | **239.6** | 0 |

**Математическое обоснование.**

1. **Без сглаживания PP = ∞.** MLE даёт $P(w\mid h) = c(h,w)/c(h)$ — ноль для любой N-граммы, не встречавшейся в Train. В Test таких событий 32% для биграмм и 69% для триграмм. Одного нуля достаточно: $\log 0 = -\infty$, сумма log-likelihood $= -\infty$, $PP = e^{+\infty} = \infty$. Модель считает тестовый текст *невозможным*, и это делает её непригодной для оценки, как бы хорошо она ни предсказывала виденные N-граммы (на них одних PP была бы всего 50.8 для биграмм и 17.6 для триграмм — иллюзия качества).

2. **Лаплас спасает от нуля, но слишком дорого.** Add-k прибавляет $k$ к каждому из $|V|$ исходов: $P = (c(h,w)+k)/(c(h)+k|V|)$. При $k=1$ и $|V| = 11\,502$ знаменатель для типичного контекста (встречавшегося считанные разы) почти целиком состоит из $k|V|$, и распределение становится почти равномерным — отсюда PP в тысячи. Уменьшение $k$ до 0.01 отбирает у виденных событий меньше массы и снижает PP втрое, но дальше (k=0.001) PP снова растёт: слишком мало массы остаётся на 32% невиденных событий. На графике PP(k) в ноутбуке видна U-образная кривая для обоих порядков, и обе лежат намного выше интерполяции.

3. **Интерполяция лучше, потому что перераспределяет массу осмысленно.** Невиденная триграмма получает не «равномерный» кусочек, а вероятность из биграммной и униграммной моделей — то есть учитывает, что обычно следует за последним словом контекста и какие слова вообще частотны. Подобранные λ отдают 60% массы униграммам — сигнал, что контексты в этом корпусе слишком разрежены и модель большую часть времени вынуждена опираться на частоты отдельных слов.

4. **Биграммы vs триграммы.** При аддитивном сглаживании триграммы проигрывают биграммам в 4–5 раз: доля невиденных триграмм вдвое выше. С интерполяцией триграммная модель, откатываясь к младшим порядкам, обгоняет биграммную, но лишь чуть (239.6 против 243.0): на ~6 тыс. коротких документов дополнительный порядок почти не добавляет информации.

5. **Перплексия сравнима только при одинаковом словаре.** `[UNK]` — самый частый «токен» ($P_{uni}(\text{[UNK]}) = 0.154$), предсказать его легко, и он занижает общую PP. Если считать PP интерполяции только по токенам ≠ `[UNK]`, получится 665.7 (биграммы) и 649.1 (триграммы) против 243.0 и 239.6 по всем. Поэтому PP ≈ 240 — не абсолютная мера качества, при другом `MIN_FREQ` числа были бы другими. Методы сглаживания у нас сравниваются при одном и том же словаре, так что сравнение честное. Частотный `[UNK]` отчасти объясняет и большой вес униграмм.

### 9. Генерация

Марковская цепь по счётчикам триграмм: старт с контекста `<s> <s>`, на каждом шаге сэмплируется следующее слово из наблюдённого распределения продолжений, стоп по `</s>` или 30 токенов. Пять текстов триграммной модели (seed=42):

1. `никто не сможет пиздеть на [UNK] приехала чтобы [UNK] в [UNK] нигеров [UNK] хотя даже на это тупоголовое еблище [UNK] [UNK] терпила`
2. `я понимаю анончики что я щас оторву тебе голову не [UNK] про пиписьки с радио свобода вот поэтому это нихуя не сделаешь и будешь искать хохлов под кроватью меня блять`
3. `конкретно тебе выше уже [UNK] [UNK] бы сам институт измены не изобрели [UNK] беда если блядь то баба [UNK] [UNK] и буду душить ее [UNK] одна история охуительнее другой просто`
4. `полно [UNK] влияния [UNK] во главе нигр пытаются победить [UNK] угрозу тред [UNK] аннексию чехословакии высер шлюхи`
5. `хер ты где на [UNK] [UNK] [NUM] кг за счет [UNK] пусть и больше [UNK] дебил`

Для сравнения в ноутбуке есть и пять текстов биграммной модели.

**Оценка.**
- **Грамматическая связность локальная.** Внутри окна из 2–3 слов фразы почти всегда правильны: «оторву тебе голову», «будешь искать хохлов под кроватью», «пытаются победить угрозу», «одна история охуительнее другой» — согласование по роду/числу/падежу соблюдено, потому что каждый переход буквально скопирован из корпуса.
- **Смысловая адекватность отсутствует** на дистанции больше 3–4 слов: в тексте 2 речь идёт то об угрозе («оторву тебе голову»), то о «радио свобода», то о «хохлах под кроватью»; стыки фрагментов ломают и грамматику («это нихуя не сделаешь»). Модель порядка 2 не помнит, с чего началось предложение.
- **Биграммы** дают более разнообразный, но менее связный текст: согласование держится только между соседними словами, фразы чаще рвутся («ты в мире есть он же поехала его хватит»).
- **`[UNK]` частый** — прямое следствие 15% `[UNK]` в Train. Спец-токены появляются в правдоподобных позициях («[NUM] кг»), что подтверждает пользу замены шума токенами, а не удаления.
- Это ожидаемая граница метода: N-граммная модель — это память о локальных переходах без семантики и без длинного контекста, что и мотивирует нейросетевые языковые модели.

## Короткие ответы на вероятные вопросы

- **Почему `target_group = women`, если в тексте нет речи о женщинах?** Метка поставлена по ключевым словам (`Identifiers`), а не по смыслу: «блядь», «сука» автоматически дают `women`. Метки шумные; для стратификации это не критично.
- **Почему стоп-слова не удалены?** Языковой модели нужен порядок всех слов, иначе ломаются грамматика и смысл (отрицания). Стоп-слова только проанализированы; доменный список (без «ты/вы» и отрицаний) — задел для классификации.
- **Почему «!!!» и «)))» не удалены вместе с пунктуацией?** В этом домене они несут сигнал — усиление, издёвку, крик. Они заменены токенами `[EMPH]`, `[SMILE]`, `[SAD]`, чтобы модель видела их как класс, а не тысячу разных «!!!!!».
- **Почему `@` заменяется пробелом, а не на `[USER]`?** На 2ch `@` — разделитель в «@-пастах», после него идут обычные русские слова. Правило `@ник → [USER]` оставлено только для латинских ников вплотную к `@`, но в Train таких нет — это проверено регуляркой.
- **Почему дубликаты удалены до сплита?** Иначе Test содержит копии Train, и перплексия занижается: модель «предсказывает» то, что видела.
- **Почему `[UNK]` заменяется уже в Train?** Чтобы у `[UNK]` были ненулевые счётчики; иначе на Test каждое неизвестное слово — нулевое событие даже со сглаживанием по контексту.
- **Почему перплексия через логарифм?** Произведение $N$ вероятностей $<1$ уходит под порог float64 (~$10^{-308}$) уже при нескольких сотнях токенов. Сумма логарифмов — обычное число.
- **Что такое перплексия интуитивно?** Средний «эффективный размер выбора»: PP = 243 значит, что модель в среднем «колеблется» между 242 равновероятными словами на каждом шаге. Равномерная модель дала бы $|V| = 11\,502$.
- **Можно ли сравнить вашу PP с PP другой модели/статьи?** Только при том же словаре и той же токенизации. Доля `[UNK]` сильно влияет на число: без учёта `[UNK]`-позиций наша PP ≈ 650–670, а не 240.
- **Почему стемминг дал словарь меньше, чем лемматизация?** На словарных словах они сжимают одинаково (≈ −49.5%). Разница — из мата и сленга вне словаря pymorphy3: стеммер сводит их формы к одной основе, а лемматизатор угадывает для разных форм разные (часто несуществующие) леммы.
- **Почему для домена выбран стемминг/гибрид, а не лемматизация?** Ключевые для hate speech слова — мат и сленг — как раз вне словаря лемматизатора, и там он работает хуже стеммера.
- **Почему память Левенштейна O(min(n,m)), а не O(1)?** Для ячейки нужна вся предыдущая строка, а не одно значение; но нужны только две строки, и мы делаем строку короткой.
- **Почему индекс удалений точен?** Если $lev(a,b) \le 2$, то, удалив из $a$ и $b$ «лишние» символы, получим общую подстроку; поэтому пара обязательно попадёт в одну корзину. Ложные срабатывания отсеивает точный алгоритм.
